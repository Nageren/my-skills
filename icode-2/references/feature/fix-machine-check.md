# fix-machine-check - 修复机器检查

自动检测 CR 的机器检查结果，分析失败原因，并协助修复代码。

## 执行流程

```
开始
  │
  ▼
获取 CR 编号（参数 / 自动检测）
  │
  ├─ 无法获取 → 告知原因，退出
  │
  ▼
获取机器检查结果 (get_machine_check)
  │
  ▼
检查是否有问题（遍历 operations，检查 status/score）
  │
  ├─ 无问题 → 输出"机器检查通过"，退出
  │
  ▼
【修复循环】(最多 N 次，默认 5 次)
  │
  ├─ 1. 输出问题详情（检查项、失败原因、行内评论）
  │
  ├─ 2. Agent 分析问题并修复代码
  │
  ├─ 3. 调用 submit-cr 提交
  │
  ├─ 4. 等待 5 秒
  │
  ├─ 5. 重新获取机器检查结果
  │
  ├─ 6. 检查是否通过
  │   │
  │   ├─ 通过 → 输出"修复成功"，退出
  │   │
  │   └─ 未通过 → 继续循环
  │
  └─ 达到最大次数 → 输出"修复失败"，退出
```

## 快速使用

```bash
# 自动检测当前 CR
./fix-machine-check.sh

# 指定 CR 编号
./fix-machine-check.sh 120247220

# 指定最大重试次数
./fix-machine-check.sh 120247220 10
```

## 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| CR 编号（第1个位置参数） | 自动检测 | CR 的 change number |
| 最大重试次数（第2个位置参数） | 5 | 修复循环的最大次数 |

## 机器检查项说明

| 检查项 | changeType | 说明 |
|--------|------------|------|
| 编码规范 | `CODE_STYLE` | 代码格式、命名规范等 |
| 缺陷检查 | `STATIC_CHECK` | 静态代码分析，潜在 bug |
| 语言合规 | `LANGUAGE_CHECK` | 语言规范检查 |
| 开源合规 | - | 开源许可证检查 |

## 检查结果字段

```json
{
  "operations": [
    {
      "name": "编码规范, 来自于 CodeStyle",
      "changeType": "CODE_STYLE",
      "status": "SUCCESS",
      "score": 1,
      "comment": "检查结果说明",
      "lineComments": {
        "src/main.go": [
          {
            "line": 42,
            "message": "变量名不符合规范"
          }
        ]
      }
    }
  ]
}
```

## Agent 修复指南

当机器检查失败时，Agent 需要：

### 1. 分析问题

从检查结果中提取：
- **检查项名称** (`name`)：了解是哪类检查
- **失败原因** (`comment`)：理解具体问题
- **行内评论** (`lineComments`)：定位具体代码位置

### 2. 读取相关文件

根据 `lineComments` 中的文件路径，读取相关代码。

### 3. 修复代码

根据问题类型修复：

| 问题类型 | 修复方法 |
|----------|----------|
| 变量命名 | 按规范重命名（camelCase/snake_case） |
| 缩进问题 | 统一使用 tab 或 space |
| 未使用变量 | 删除或添加使用 |
| 缺少注释 | 添加必要注释 |
| 潜在空指针 | 添加空值检查 |

### 4. 提交修复

修复完成后，调用 submit-cr 提交：

```bash
./submit-cr.sh
```

## 注意事项

1. **轮询间隔**：每次检查间隔 5 秒，等待机器检查完成
2. **最大重试**：默认 5 次，可通过参数调整
3. **Agent 介入**：修复代码需要 Agent 分析和执行
