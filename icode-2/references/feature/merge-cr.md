# merge-cr - 合入 CR

尝试打分 +2 并合入 CR，通过打分结果判断是否有合入权限。

## 执行流程

```
开始
  │
  ▼
获取 CR 编号（参数 / 自动检测）
  │
  ├─ 无法获取 → 告知原因，退出 (1)
  │
  ▼
尝试打分 +2 (set_review_score)
  │
  ├─ 打分成功 ─────────────────────────────────────
  │   │
  │   ├─ 尝试合入 (submit_review)
  │   │   │
  │   │   ├─ 成功 → 输出"合入成功"，退出 (0)
  │   │   │
  │   │   └─ 失败 → 输出失败原因，退出 (1)
  │   │
  └─ 打分失败 ─────────────────────────────────────
      │
      └─ 输出"无合入权限"，退出 (1)
```

## 快速使用

```bash
# 自动检测当前 CR
./merge-cr.sh

# 指定 CR 编号
./merge-cr.sh 120247220
```

## 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| CR 编号（`$1`） | 自动检测 | CR 的 change number |

## 退出码说明

| 退出码 | 含义 | 说明 |
|--------|------|------|
| 0 | 成功 | CR 已合入 |
| 1 | 失败 | 无 CR / 无权限 / 打分失败 / 合入失败 |

## 权限检测说明

脚本通过尝试 **打分 +2** 来检测权限：

- **打分成功**：说明用户有该仓库的评审权限，继续尝试合入
- **打分失败**：说明用户没有评审权限，输出错误信息

## 合入失败常见原因

| 原因 | 说明 | 解决方法 |
|------|------|----------|
| 无评审权限 | 用户不是仓库成员或权限不足 | 联系仓库管理员添加权限 |
| 机器检查未通过 | 存在代码规范或缺陷问题 | 执行 fix-machine-check 修复 |
| 未解决的评审意见 | 有评审人提出的问题未处理 | 回复或解决评审意见 |
| 代码冲突 | 目标分支有新提交导致冲突 | Rebase 并解决冲突后重新提交 |
| 缺少必要审批 | 需要特定角色审批 | 联系有权限的评审人 |

## 完整工作流示例

```bash
# 场景 1：有权限，合入成功
./merge-cr.sh
# 输出: ✓ CR #120247220 合入成功！

# 场景 2：无权限
./merge-cr.sh
# 输出: ✗ 打分失败，无合入权限

# 场景 3：有权限但合入失败
./merge-cr.sh
# 输出: ✗ CR 合入失败
#       失败原因: 机器检查未通过
```

## 注意事项

1. **权限检测**：通过打分 +2 来检测权限
2. **打分覆盖**：如果之前有其他评分，新评分会覆盖
3. **合入不可逆**：合入后 CR 状态变为 MERGED，无法撤销
