# submit-acr - AI 代码评审

自动触发 AI 代码评审并分析结果，发现需要修复的问题时退出等待 Agent 修复。

## 执行流程

```
开始
  │
  ▼
获取 CR 编号（参数 / 自动检测）
  │
  ├─ 无法获取 → 告知原因，退出 (1)
  │
  ▼
【主循环】(最多 MAX_LOOPS 次，默认 10)
  │
  ├─── AI 代码评审 ────────────────────────
  │    │
  │    ├─ 触发 AI 评审 (start_ai_review)
  │    │
  │    ├─ 轮询结果 (get_ai_review, 10s/次)
  │    │   │
  │    │   ├─ 超时 (默认 20min) → 退出 (1)
  │    │   ├─ 状态 FAIL/TIMEOUT → 退出 (1)
  │    │   └─ 状态 SUSS → 继续处理结果
  │    │
  │    ├─ 过滤 severityScore >= N (默认 5) 的问题
  │    │   │
  │    │   ├─ 无问题 → 流程成功，退出 (0)
  │    │   │
  │    │   └─ 有问题 → 输出问题详情，退出 (2)
  │    │               等待 Agent 修复后重新运行
  │    │
  └─── 达到最大循环次数 → 退出 (1)
```

## 快速使用

```bash
# 自动检测当前 CR，使用默认参数
./submit-acr.sh

# 指定 CR 编号
./submit-acr.sh 120247220

# 指定最大循环次数
./submit-acr.sh 120247220 10

# 完整参数
./submit-acr.sh 120247220 10 1200 5
# 参数顺序: CR编号 最大循环次数 AI超时秒数 严重度阈值
```

## 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| CR 编号（`$1`） | 自动检测 | CR 的 change number |
| 最大循环次数（`$2`） | 10 | 主循环最大次数 |
| AI 评审超时（`$3`） | 1200 (20min) | AI 评审轮询超时秒数 |
| 严重度阈值（`$4`） | 5 | 需要修复的 severityScore 阈值 |

## 退出码说明

| 退出码 | 含义 | Agent 动作 |
|--------|------|-----------|
| 0 | 成功：AI 评审通过 | 无需操作 |
| 1 | 失败：无 CR / 超时 / 达到最大次数 | 报告错误 |
| 2 | 需要 Agent 修复 | 分析问题，修复代码，提交后重新运行 |

## AI 评审问题严重度说明

| severityScore | 严重程度 | 说明 | 默认处理 |
|---------------|----------|------|----------|
| 1-3 | 低 | 代码风格、命名建议 | 忽略 |
| 4 | 中低 | 轻微优化建议 | 忽略 |
| 5-6 | 中 | 代码优化、性能改进 | **需要修复** |
| 7-10 | 高 | 潜在 bug、安全问题 | **需要修复** |

## Agent 修复指南

### 收到退出码 2 时

脚本会输出需要修复的问题详情，Agent 需要：

1. **分析问题** - 查看文件、行号、严重度、问题描述
2. **读取相关文件** - 根据输出的文件路径读取代码
3. **修复代码** - 使用 Edit 工具修复代码
4. **提交修复** - 使用 submit-cr 提交
5. **重新运行检查** - 继续 AI CR 流程

### 常见问题类型修复

| 问题类型 | 修复方法 |
|----------|----------|
| 缺少错误处理 | 添加 error check |
| 潜在空指针 | 添加空值检查 |
| 性能问题 | 优化算法/数据结构 |
| 安全问题 | 修复安全漏洞 |

## 完整工作流示例

```bash
# 1. 提交 CR
./submit-cr.sh

# 2. 运行 AI CR 完整流程
./submit-acr.sh

# 3. 如果有问题需要修复，脚本会退出并输出问题
#    Agent 分析问题并修复代码

# 4. 修复后重新提交
./submit-cr.sh

# 5. 继续运行 AI CR 流程
./submit-acr.sh 120247220

# 重复 3-5 直到通过
```

## 注意事项

1. **轮询间隔**：AI 评审每 10 秒轮询一次
2. **超时设置**：默认 20 分钟，可根据代码量调整
3. **严重度阈值**：默认 5，可降低以检查更多问题
4. **Agent 介入**：修复代码需要 Agent 分析和执行
